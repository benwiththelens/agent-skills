# 🚀 Autonomous Jules Pipeline — System Architecture & Design Specification

> **A blueprint for decoupled, high-velocity agentic software development.**  
> How VANTAGE orchestrates parallel Google Jules cloud VMs, Graphify AST code intelligence, automated test gating, and multi-model audit pipelines.

---

## 1. Executive Summary & Core Philosophy

The **Autonomous Jules Pipeline** is an asynchronous, event-driven development architecture. It bridges high-level systems architecture with parallelized cloud-agent execution, allowing a single architect to coordinate massive monorepo builds while eliminating the manual keyboard grind.

### The 4 Pillars of the Architecture:
1. **Decoupled Asynchrony:** The architect and orchestrator never wait on code generation. Tasks are dispatched to cloud VMs (Google Jules) and monitored via headless cron daemons.
2. **Graph-Enriched Context (Graphify AST):** Rather than blindly dumping massive codebases into prompt windows, tasks are injected with exact Abstract Syntax Tree (AST) node dependencies, types, and file relationships.
3. **Autonomous Feedback Resolution:** When a cloud agent pauses for human feedback or plan approvals, an automated OpenClaw subagent inspects the git patch, resolves the blocker, and approves execution.
4. **Strict Audit & Test Gatekeeping:** Code generated by cloud agents is **never blindly trusted**. PRs must pass high-reasoning security audits and a 100% automated test suite pass before merging into `main`.

## 3. Subsystem Deep-Dive

### 3.1 Subsystem 1: Spec Atomizer & Frontmatter Standard
Tasks are staged as individual markdown files in `vault/01-ACTIVE/jules-queue/`. Every task must follow strict frontmatter and boundary rules:

```yaml
---
repo_path: "gs1-link-engine"
title: "Phase 9.2: GS1 2D DataMatrix (ISO/IEC 16022) & Dual-Symbol Switcher (@gs1/barcode-vector)"
priority: "high"
depends_on: "SPEC-P9-core-types"
tags:
  - jules-spec
  - phase-9
  - symbology
---
# 🎯 Task Spec: [Task Name]

## 📌 1. Objective & Context
[Concise, 2-sentence explanation of what is being built and why]

## 🛠️ 2. Functional Requirements
- [ ] Explicit File 1 changes (`packages/...`)
- [ ] Explicit File 2 changes (`apps/...`)
- [ ] Strict type definitions and interfaces

## 🧪 3. Verification & Testing
- [ ] Specific test file path (`packages/.../__tests__/feature.test.ts`)
- [ ] Expected test assertions
- [ ] Assertion that `npm test` passes 100%
```

**Golden Rule:** Keep specs under 200 lines of modified code. Large monolithic prompts cause agent context drift; small, atomic specs produce 100% pass rates.

---

### 3.2 Subsystem 2: Graphify AST Code Intelligence
Before dispatching a task to Jules, `scripts/jules-queue-dispatcher.mjs` queries the local **Graphify AST Analysis Index** (`.graphify_analysis.json`).

* **What it does:** Scans the codebase using TypeScript AST parsers to map every file node, class, function export, and module dependency.
* **Why it matters:** Instead of Jules guessing how `@gs1/schema` exports types or how `apps/resolver` handles routing, the dispatcher automatically appends the exact relevant AST subgraph to the prompt payload.

---

### 3.3 Subsystem 3: Queue Dispatcher & Quota Governor
The dispatcher (`jules-queue-dispatcher.mjs`) manages outbound traffic and API quotas:

* **State Tracking (`jules-state.json`):** Tracks session IDs, spec filenames, dispatch timestamps, and PR URLs.
* **Daily Quota Safety Buffer:** Enforces a daily dispatch cap (e.g., 80/100 sessions) to prevent unexpected quota exhaustion.
* **Source Resolution:** Automatically resolves GitHub source context handles (`sources/github/owner/repo`) from the Google Jules client API.
* **Discord Telemetry:** Broadcasts immediate rich alerts to Discord whenever a task is dispatched.

---

### 3.4 Subsystem 4: Autonomous Telemetry & Feedback Orchestrator
Jules sessions occasionally pause in `AWAITING_USER_FEEDBACK` or `REQUIRES_APPROVAL`. The `jules-notifier.mjs` daemon runs on OpenClaw cron:

1. **State Sweep:** Polls active sessions via `jules-client.mjs list-sessions`.
2. **Autonomous Subagent Dispatch:** If an agent requests feedback or plan approval:
   * It inspects the latest activity logs and git diffs.
   * Compares the agent's proposal against the original spec requirements.
   * Dispatches `jules-client.mjs approve-plan` or sends a precise technical clarification.
3. **PR Staging:** When a session reaches `COMPLETED`, records the PR URL into state with status `KIMI_K3_AUDIT_REQUIRED`.

---

### 3.5 Subsystem 5: Multi-Model Audit & Merge Gatekeeper
The Merge Gatekeeper ensures zero regressions across the monorepo:

* **Diff Auditing:** Uses a high-reasoning model (`moonshot/kimi-k3` or `gemini-3.7-flash`) to audit code diffs for compliance liabilities, security leaks, or broken math.
* **Sequential Branch Integration:** Automatically pulls remote PR branches, merges them into local `main`, and resolves package/lockfile conflicts.
* **Compilation & Test Suite Enforcement:** Runs `npm run build:packages` and `npm test`. If even one test fails, the merge is halted.
* **Git Push & CI/CD Trigger:** Once verified, pushes `main` to GitHub, which triggers Cloudflare Edge Anycast deployments.

## 4. Key Engineering Gotchas & Hardened Solutions

| Challenge / Papercut | Root Cause | Engineering Solution |
| :--- | :--- | :--- |
| **Edge Bundle Failure (Chromium/Playwright)** | Cloudflare Workers run on V8 isolates and cannot bundle native C++ Chromium binaries. | Standardize all PDF generation on pure JavaScript `pdf-lib`. |
| **Container IPv6 Network Drops** | Docker containers on Linux hosts lacking IPv6 routes fail on GitHub API calls. | Force global IPv4 resolution (`dns.lookup { family: 4 }`) in all automation scripts. |
| **Merge Lockfile Choke** | Multiple concurrent branches adding dependencies cause Git lockfile conflicts. | Scripted lockfile conflict cleaner + automated `npm install` regeneration during the merge pass. |
| **Recall Redirect Liability** | Browser caching of HTTP 301/308 redirects prevents emergency lot recall notices. | Enforce strict `307 Temporary Redirect` policy across all edge resolvers. |
